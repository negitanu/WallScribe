# WallScribe デザイン品質基準

Web UI と HTML / PDF / XLSX のすべてを対象に、Awwwards・Webby Awards・FWA の受賞作に並ぶ完成度を目標とする。受賞相当という自己認定や、根拠のない点数付けで完了を判定しない。

## 表現の方針

「設定を、読み解ける設計書に。」を中心に、藍色のインク、白い紙面、明確な罫線、意味を持つ色で構成する。視覚的な個性は、設定から文書へ変換する工程と情報の構造を表す。操作や設定値の読み取りを妨げる装飾は追加しない。

Webby の公式審査項目にある内容、構造・ナビゲーション、視覚デザイン、機能、インタラクション、全体体験を品質確認に使う。
参考: https://www.webbyawards.com/judging-criteria/

## 改善ループ

1. 架空の代表設定を使い、全形式で同じデータを生成する。実データを外部に送らない。Web 検証では `WALLSCRIBE_DISABLE_CLEANUP_THREAD=1` と専用の `UPLOAD_FOLDER` を設定する。
2. Web / HTML をデスクトップ幅と 390px のモバイル幅で実際に表示する。検索、入力への移動、ファイル選択、プリセット、エラーと完了画面を操作する。
3. PDF は本番の WeasyPrint で生成し、全ページを画像に変換する。Excel は再読込で値・書式を確認し、表計算ソフトで画面と印刷プレビューを確認する。
4. 問題を具体的に記録し、影響する形式のソースを修正する。
5. 同じ入力と表示幅で再生成・再表示し、修正した問題が解消し、周辺に新しい問題がないことを確認する。関連する回帰テストを実行する。
6. 未検証の形式・状態は明記する。未検証を合格扱いしない。

## 完了条件

- タイトル、本文、メタデータ、表、ステータスの情報階層が明確である。
- Web と各文書で色、言葉、見出し、余白が整合する。許可・拒否・重要度は文字でも識別できる。
- 本文のコントラスト比は原則 4.5:1 以上、大きな文字は 3:1 以上を確保する。
- キーボードで主要操作に到達でき、フォーカスが見える。検索結果や進捗の変化を支援技術が認識できる。
- モバイルでページ全体が横に溢れない。多列の表と構造図は文字を潰さず、専用領域内でスクロールできる。
- 長いホスト名、IP、オブジェクト名、コメント、複数行、空の設定、複数 VDOM / vsys、HA 構成を確認する。
- 動きを減らす設定に対応し、装飾のための外部通信・大きな依存を追加しない。
- PDF の文字化け、切れ、重なり、孤立した見出しがない。ページ番号と表題が適切で、繰り返す表見出しと改ページを確認する。
- XLSX の文字が行高・列幅に収まり、見出し固定、印刷範囲、用紙、縮尺、ページ番号が適切である。Excel の行高上限を超える値は別途確認する。
- 設定値を装飾や丸めで変えない。推定・未解析・人の判断を必要とする事項を確定情報のように見せない。
- 代表例が見栄えよく表示されるだけでなく、実際の利用者による操作確認とフィードバックで改善を続ける。

## 2026-10-01 の検証範囲

Web のデスクトップ / 390px 表示、入力への移動、HTML の検索、HTML の多列表と構造図の表示を確認。モバイルで日本語が一文字ずつ縦に折り返される問題を修正した。架空の設定から XLSX の 15 シートを生成・再読込し、印刷設定を確認した。

本環境は WeasyPrint に必要なネイティブライブラリが不足している。PDF の CSS は改善したが、PDF エクスポーターの実際の生成結果は未検証。XLSX の LibreOffice プレビューは Excel 本体での表示検証とは区別する。複数 VDOM / HA と全 UI 状態の目視検証、性能測定、ユーザーテスト、外部審査は未完了。
